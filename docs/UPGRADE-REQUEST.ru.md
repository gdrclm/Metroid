**1. P0 — исправить проблемы контроллера и взаимодействий**

**1. Спуск через платформу разрешать только на односторонней опоре.**  
В `physics.js` сочетание «вниз + прыжок» проверяет только `grounded`, затем сдвигает героя вниз на 2 пикселя. Тип поверхности не проверяется. Это создаёт риск проникновения в обычный твёрдый пол, потому что разрешение столкновений рассчитано преимущественно на пересечение границы снаружи.

- [ ] Проверять конкретную опору под персонажем.
- [ ] Разрешать спуск только при `kind === "oneWay"`.
- [ ] На твёрдом полу не изменять координату героя.
- [ ] Добавить регрессионные проверки на обычном полу, краю и движущейся платформе.

Источник: [physics.js](https://github.com/gdrclm/Metroid/blob/9389e824cfbd7fd2a8e4704721c8c13e56d7e676/src/physics.js#L127).

**2. Проверять безопасность точки локального возврата.**  
Сейчас `safePoint` обновляется при стоянии на поверхности без пересечения опасности. Это не гарантирует безопасное появление: точка может находиться на краю или на платформе, которая уже уехала.

- [ ] Проверять свободный объём для тела.
- [ ] Проверять наличие опоры после возврата.
- [ ] Не сохранять край как безопасную позицию.
- [ ] Для движущейся опоры хранить привязку либо использовать ближайшую статичную площадку.
- [ ] При невалидной позиции использовать предыдущую проверенную точку.

Источник: [game.js](https://github.com/gdrclm/Metroid/blob/9389e824cfbd7fd2a8e4704721c8c13e56d7e676/src/game.js#L425).

**3. Запретить взаимодействия сквозь стены.**  
`findNearby()` выбирает объекты по расстоянию и приоритету. Проверки преграды между героем и объектом нет.

- [ ] Проверять доступность объекта со стороны игрока.
- [ ] Для двери использовать отдельную зону взаимодействия.
- [ ] Для верхних и нижних этажей учитывать принадлежность проходу.
- [ ] Проверить рычаги, награды и NPC за тонкой перегородкой.

**4. Исправить сообщения о недоступных предметах.**  
Любое невыполненное `target.requires` сейчас выводит сообщение: «Механизм удерживает смотритель двора». Оно подходит рычагам арены, но не верхнему секрету `P03`, требующему зацепа.

- [ ] Добавить `lockedReason` для интерактивных объектов.
- [ ] Разделить причины: способность, сюжетное условие, направление открытия.
- [ ] Не выдавать сведения о смотрителе возле предмета, который с ним не связан.

Источник для пунктов 3–4: [game.js](https://github.com/gdrclm/Metroid/blob/9389e824cfbd7fd2a8e4704721c8c13e56d7e676/src/game.js).

**5. Сделать проверку видимости врагов геометрически корректной.**  
Сейчас обнаружение использует горизонтальную проверку на высоте врага. Вертикальная разница учитывается порогом, но линия к фактическому центру героя не проверяется.

**38. Сделать обучение зависимым от успешного действия.**  
Подсказка исчезает, когда игрок выполнил рывок или прыжок от стены, а не только спустя время.

**39. Разделить будущие барьеры по облику.**  
Затопленный тоннель и Архив сейчас используют общий рисунок объекта `barrier`. Им нужны разные признаки: глубина и течение для тоннеля, механизм и печати для Архива.

**Рекомендуемый порядок работ**

| Пакет | Содержание | Критерий результата |
|---|---|---|
| **1. Надёжность** | Пункты 1–5 | Нет проваливания, взаимодействий сквозь стены и опасных возвратов |
| **2. География** | 6–8, 19–24 | Движение по миру соответствует карте |
| **3. Комнаты** | 9–14 | У каждого помещения есть узнаваемая задача или событие |
| **4. Движение и камера** | 15–18 | Учебные участки понятны и проходимы на целевых экранах |
| **5. Сокращения и бой** | 25–34 | Возвращения короче, повторные попытки не утомляют |
| **6. Подача** | 35–44 | Способности, регионы и ориентиры различаются без поясняющего текста |
| **7. Приёмка** | 45–50 | Срез пройден целиком обычным вводом и проверен новым игроком |

**Для ближайшей версии я бы первым делом сделал пункты 1, 2, 6, 8, 15, 19, 25 и 34.** Они сильнее всего влияют на доверие к управлению, понимание пространства и желание продолжать исследование.
